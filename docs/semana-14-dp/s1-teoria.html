Parte 1

De la recursión a la tabla

El mismo subproblema aparece muchas veces: se calcula una vez y se guarda.

Subproblemas repetidos

Formas de sumar n con un dado

def formas(s):          # formas de sumar s
    if s == 0:
        return 1
    total = 0
    for d in range(1, 7):   # el último dado
        if d <= s:
            total += formas(s - d)
    return total
sin memoria, n = 20
0.09 s
sin memoria, n = 25
1.53 s
tabla, n = 10⁶
0.012 s

formas(20) llama a formas(19), …, formas(14); formas(19) vuelve a llamar a formas(18), …, formas(13). Los mismos valores se calculan una y otra vez y la cantidad de llamadas crece de forma exponencial.

Solo el cálculo. PyPy 3.11, Apple M4.

Mover el control para ver cuántas llamadas hace la versión sin memoria. Solo hay n + 1 valores distintos de s; todo lo demás es trabajo repetido.

Memoización y tabla

Guardar cada respuesta

Memoización: recursión con caché 
from functools import cache

@cache
def formas(s):
    if s == 0:
        return 1
    total = 0
    for d in range(1, 7):
        if d <= s:
            total += formas(s - d)
    return total % MOD

Cada s se calcula una vez: O(6n). Pero la recursión llega a profundidad n. Con setrecursionlimit(10**6), n = 5000 funcionó y n = 6000 dio RecursionError.

Tabla: de los casos pequeños a los grandes 
dp = [0] * (n + 1)
dp[0] = 1
for s in range(1, n + 1):
    total = 0
    for d in range(1, 7):
        if d <= s:
            total += dp[s - d]
    dp[s] = total % MOD

Es la misma fórmula, en un bucle. Cuando se calcula dp[s], los dp[s − d] ya están en la tabla. No hay recursión ni límite de profundidad.

En el curso se usa la tabla (bottom-up). La memoización sirve para pensar la fórmula; después se traduce a un bucle. Además, cada llamada a función cuesta más que una vuelta de un bucle. Mediciones con PyPy 3.11 en un Apple M4.

Las cinco piezas

Qué hay que decidir en toda DP

PiezaPreguntaDice Combinations
Estado¿Qué significa dp[s]?Formas de sumar s.
Transición¿Cómo sale de estados más pequeños?dp[s] = dp[s − 1] + … + dp[s − 6], según el último dado.
Caso base¿Qué se sabe sin calcular?dp[0] = 1: la forma vacía.
Orden¿En qué orden se llena la tabla?s de 1 a n, porque dp[s] usa valores menores.
Respuesta¿Dónde queda?dp[n].

El costo es la cantidad de estados por el costo de cada transición: aquí n · 6.

Escribir las cinco piezas en el tablero antes de programar cada problema de hoy. El estado es la decisión más difícil: tiene que guardar todo lo necesario para seguir y nada más.

Hay N piedras con alturas h₁, …, h_N. Una rana empieza en la piedra 1 y salta a la piedra i + 1 o i + 2. Cada salto de i a j cuesta |hᵢ − hⱼ|.

El costo mínimo.

30 10 60 10 60 50

Enunciado original: https://atcoder.jp/contests/dp/tasks/dp_a

Leer el enunciado con el grupo y resolver el ejemplo a mano: 1 → 3 → 5 → 6 cuesta 30 + 0 + 10 = 40.

Idea · AtCoder EDPC A

Frog 1

Pregunta para el grupo

¿Desde qué piedras se puede llegar a la piedra i? ¿Qué hay que saber de ellas?

Desde i − 1 o desde i − 2. Hace falta el costo mínimo para llegar a cada una.
dp[i] = min(dp[i − 1] + |hᵢ − hᵢ₋₁|, dp[i − 2] + |hᵢ − hᵢ₋₂|), con dp[0] = 0 y la respuesta en dp[N − 1]. Es O(N).

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso. Nombrar las cinco piezas.

Solución · AtCoder EDPC A · Frog 1

El mejor de los dos saltos

h
dp

Con las piedras indexadas desde 0. Por ejemplo, dp[2] = min(20 + 50, 0 + 30) = 30.

def main():
    n = int(input())
    h = list(map(int, input().split()))
    dp = [0] * n
    dp[1] = abs(h[1] - h[0])
    for i in range(2, n):
        dp[i] = min(dp[i - 1] + abs(h[i] - h[i - 1]),
                    dp[i - 2] + abs(h[i] - h[i - 2]))
    print(dp[n - 1])

main()

Con N = 10⁵ tardó 0.03 s (PyPy 3.11, Apple M4). Frog 2, de la tarea, permite saltos de hasta K piedras: el min recorre K opciones y el costo es O(N · K).

3

Enunciado original: https://cses.fi/problemset/task/1633

Error común: la recursión sin memoria, o con memoria pero con n = 10⁶ de profundidad. Otro: olvidar el módulo. Caso a probar: n = 7, cuya respuesta es 63 (no 64: falta la forma "7", que no existe).

Solución · CSES 1633 · Dice Combinations

dp[s] suma los seis anteriores

MOD = 10**9 + 7

def main():
    n = int(input())
    dp = [0] * (n + 1)
    dp[0] = 1
    for s in range(1, n + 1):
        total = 0
        for d in range(1, 7):
            if d <= s:
                total += dp[s - d]
        dp[s] = total % MOD
    print(dp[n])

main()

Avanzar paso a paso: en amarillo la casilla que se calcula y en azul las que se suman. O(6n). Con n = 10⁶ tardó 0.04 s (PyPy 3.11, Apple M4).

Monedas

Tres preguntas sobre las mismas monedas

Monedas 2, 3 y 5. Para cada suma s:

  • Mínimo de monedas (Minimizing Coins): dp[s] = 1 + min(dp[s − m]).
  • Secuencias ordenadas (Coin Combinations I, de la tarea): dp[s] = Σ dp[s − m]. 2 + 3 y 3 + 2 cuentan como dos.
  • Formas sin orden (Coin Combinations II): se procesa moneda por moneda, así que 2 + 3 y 3 + 2 son una sola.

Para s = 9: mínimo 3 (2 + 2 + 5), 8 secuencias y 3 formas.

"—" en la columna del mínimo indica que esa suma no se puede formar (s = 1). Las tres usan la misma tabla de 0 a x; cambia la transición y, en el último caso, el orden de los bucles.

Idea · CSES 1634

Minimizing Coins

Pregunta para el grupo

Si la última moneda de una solución óptima para s es m, ¿qué se sabe del resto?

El resto forma s − m con el mínimo de monedas. Así que dp[s] = 1 + min(dp[s − m]) sobre las monedas m ≤ s.
Las sumas imposibles quedan en un valor grande (INF). Son x · n = 10⁸ pasos, así que el bucle tiene que ser simple.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.

Solución · CSES 1634 · Minimizing Coins

Una moneda menos en cada paso

def main():
    n, x = map(int, input().split())
    c = list(map(int, input().split()))
    INF = x + 1
    dp = [INF] * (x + 1)
    dp[0] = 0
    for m in c:
        for s in range(m, x + 1):
            if dp[s - m] + 1 < dp[s]:
                dp[s] = dp[s - m] + 1
    print(dp[x] if dp[x] < INF else -1)

main()

El bucle externo recorre las monedas y el interno las sumas. Para el mínimo, el orden de los bucles no cambia la respuesta.

Con n = 100 y x = 10⁶ (10⁸ pasos) tardó 0.12 s (PyPy 3.11, Apple M4).

INF = x + 1 sirve porque ninguna solución usa más de x monedas. Con la moneda m fija, s crece, así que dp[s − m] ya puede incluir monedas m: se pueden repetir, como pide el problema.

Solución · CSES 1636 · Coin Combinations II

Moneda por moneda

MOD = 10**9 + 7

def main():
    n, x = map(int, input().split())
    c = list(map(int, input().split()))
    dp = [0] * (x + 1)
    dp[0] = 1
    for m in c:
        for s in range(m, x + 1):
            dp[s] = (dp[s] + dp[s - m]) % MOD
    print(dp[x])

main()

Después de procesar las monedas c₁, …, cₖ, dp[s] cuenta las formas de sumar s usando solo esas. Cada forma se arma en el orden de las monedas, así que se cuenta una vez.

Con n = 100 y x = 10⁶ tardó 0.16 s (PyPy 3.11, Apple M4).

Con la resta condicional (if v >= MOD: v -= MOD) en lugar de % tardó 0.46 s: en PyPy el % fue más rápido. En Coin Combinations I (tarea) las sumas van por fuera; con las monedas ordenadas y un break cuando m > s tardó 0.11 s.

Idea · CSES 1638

Grid Paths I

Pregunta para el grupo

¿Desde qué casillas se llega a (i, j) en un paso?

Desde (i − 1, j), arriba, y desde (i, j − 1), a la izquierda. dp[i][j] = dp[i − 1][j] + dp[i][j − 1], y 0 si (i, j) es trampa.
Se llena fila por fila, de izquierda a derecha: así arriba e izquierda ya están calculadas. Son n² = 10⁶ estados.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.

Solución · CSES 1638 · Grid Paths I

Arriba más izquierda

dp del ejemplo. Las casillas negras son trampas.

MOD = 10**9 + 7

def main():
    n = int(input())
    g = [input() for _ in range(n)]
    dp = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if g[i][j] == "*":
                continue
            if i == 0 and j == 0:
                dp[i][j] = 1
            else:
                arriba = dp[i - 1][j] if i > 0 else 0
                izq = dp[i][j - 1] if j > 0 else 0
                dp[i][j] = (arriba + izq) % MOD
    print(dp[n - 1][n - 1])

main()

O(n²). Con n = 1000 tardó 0.04 s (PyPy 3.11, Apple M4).

Idea · AtCoder EDPC D

Knapsack 1

Pregunta para el grupo

Con los primeros i objetos y capacidad c, ¿qué dos opciones hay para el objeto i?

No tomarlo: dp[i − 1][c]. Tomarlo, si cabe: dp[i − 1][c − wᵢ] + vᵢ. dp[i][c] es el mayor de los dos.
La tabla tiene N · W = 10⁷ estados. La respuesta es dp[N][W].

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso. dp[0][c] = 0 para todo c: sin objetos, valor 0.

Mochila en 1D

Una sola fila, recorrida al revés

c

dp = [0] * (W + 1)
for w, v in objetos:

dp[i][c] solo usa la fila i − 1, así que basta una fila. Al ir de W hacia abajo, dp[c − w] todavía tiene el valor sin el objeto i.

Al derecho, dp[c − w] ya puede incluir el objeto i, y el objeto se usa varias veces.

Avanzar con los objetos del ejemplo: (3, 30), (4, 50) y (5, 60), W = 8. Al revés da 90. Al derecho da 100 (dos veces el objeto de peso 4), que es la respuesta de otro problema: la mochila con repetición. La memoria baja de N · W a W.

Solución · AtCoder EDPC D · Knapsack 1

Mochila 0/1 en una fila

def main():
    n, W = map(int, input().split())
    dp = [0] * (W + 1)
    for _ in range(n):
        w, v = map(int, input().split())
        for c in range(W, w - 1, -1):
            if dp[c - w] + v > dp[c]:
                dp[c] = dp[c - w] + v
    print(dp[W])

main()

O(N · W) = 10⁷ pasos y O(W) de memoria.

Los objetos se procesan al leerlos: no hace falta guardarlos.

Con N = 100 y W = 10⁵ tardó 0.04 s (PyPy 3.11, Apple M4).

dp[c] es el mayor valor con peso total a lo sumo c. Por eso la respuesta es dp[W] y no hace falta buscar el máximo de la fila.

Reconocer una DP

Cuándo pensar en programación dinámica

  • Pide un mínimo, un máximo o una cantidad de formas.
  • La solución es una secuencia de decisiones: qué dado, qué moneda, tomar o no un objeto.
  • Después de decidir, queda el mismo problema más pequeño.
  • Probar todas las opciones es exponencial, pero hay pocos estados distintos.
  • Un greedy tiene contraejemplo.

Antes de programar

  1. Escribir las cinco piezas.
  2. Contar estados × costo de la transición y compararlo con 10⁸.
  3. Resolver a mano los casos pequeños y comparar con la tabla.

En Python, la tabla bottom-up evita el límite de recursión y el costo de las llamadas. La DP con bitmask, la de intervalos y LIS en O(n log n) quedan fuera del programa.

Idea · AtCoder EDPC F

LCS

Pregunta para el grupo

Sea dp[i][j] el largo de la LCS de s[:i] y t[:j]. ¿Qué pasa si s[i − 1] == t[j − 1]? ¿Y si son distintos?

Si son iguales, ese carácter entra: dp[i − 1][j − 1] + 1. Si no, se descarta el último de uno de los dos: max(dp[i − 1][j], dp[i][j − 1]).
Para el string, se vuelve desde (n, m) por las decisiones que dieron cada valor, y se invierte. Son 3000² = 9·10⁶ estados.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.

Solución · AtCoder EDPC F · LCS

Llenar la tabla y volver por ella

Llenar 
def main():
    s = input()
    t = input()
    n, m = len(s), len(t)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s[i - 1] == t[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j],
                               dp[i][j - 1])
Reconstruir 
    res = []
    i, j = n, m
    while i > 0 and j > 0:
        if s[i - 1] == t[j - 1]:
            res.append(s[i - 1])
            i -= 1
            j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1
    print("".join(reversed(res)))

main()

O(n · m). Con dos strings de 3000 letras tardó 0.12 s (PyPy 3.11, Apple M4).

Resumen

Reglas para programación dinámica

  1. Escribir estado, transición, caso base, orden y respuesta antes de programar.
  2. Costo = estados × costo de cada transición.
  3. En Python, tabla bottom-up; la memoización con recursión puede fallar desde unas 6000 llamadas anidadas.
  4. Contar con orden: sumas por fuera. Sin orden: monedas por fuera.
  5. Mochila 0/1 en una fila: recorrer la capacidad de mayor a menor.
  6. Para reconstruir la solución, volver por la tabla desde la respuesta.
