Parte 1

Cuando el arreglo cambia

Las sumas prefijas de la semana 9 se calculan una vez.

Repaso

Cambiar un valor obliga a rehacer las prefijas

Con p[i] = x₁ + … + xᵢ, una suma de rango cuesta O(1). Si x_k cambia, cambian p[k], p[k + 1], …, p[n]: O(n) por cambio.

Sin las prefijas, cada consulta suma el rango en O(n). Con q consultas mezcladas con cambios, las dos formas cuestan O(n · q).

El árbol de Fenwick hace las dos operaciones en O(log n).

Parte 2

Árbol de Fenwick

Un arreglo donde cada posición guarda la suma de un bloque.

i & -i

bit[i] guarda la suma de un bloque que termina en i

i & -i es el bit 1 más bajo de i: 12 = 1100 da 4 = 100.

bit[i] guarda x de la posición i − (i & −i) + 1 hasta la i. Por ejemplo, bit[12] = x₉ + x₁₀ + x₁₁ + x₁₂.

Los índices van de 1 a n. Con el 0 el truco no funciona, porque 0 & −0 = 0.

Hacer clic en un bloque para ver su rango y el binario de i. Los impares guardan un solo valor; los múltiplos de 4 que no son de 8 guardan 4 valores; y así. -i en binario es el complemento a dos de i, por eso i & -i deja solo el bit más bajo.

Operaciones

Prefijo hacia abajo, actualización hacia arriba

def sumar(i, v):      # x_i += v
    while i <= n:
        bit[i] += v
        i += i & -i

def prefijo(i):       # x_1 + ... + x_i
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & -i
    return s

# suma de a a b
prefijo(b) - prefijo(a - 1)

prefijo(13) suma bit[13] + bit[12] + bit[8]: los bloques 13, 9–12 y 1–8, que cubren 1..13 sin repetir. Cada paso quita el bit más bajo de i, así que hay a lo sumo log₂ n pasos. sumar(5, v) actualiza bit[5], bit[6], bit[8] y bit[16]: todos los bloques que contienen la posición 5. Con n = 2·10⁵, unos 18 pasos.

Construcción

Construir el Fenwick en O(n)

bit = [0] * (n + 1)
for i in range(1, n + 1):
    bit[i] += x[i - 1]
    j = i + (i & -i)       # el bloque padre
    if j <= n:
        bit[j] += bit[i]

Cuando se llega a i, bit[i] ya tiene la suma de su bloque: los bloques menores que lo forman ya le pasaron sus sumas. Entonces se pasa bit[i] al siguiente bloque que lo contiene, i + (i & −i).

También se puede llamar sumar(i, x[i - 1]) para cada i, que cuesta O(n log n). Con n = 2·10⁵ los dos son rápidos; la versión en O(n) hace un paso por posición en lugar de hasta log₂ n.

Ejemplo: bit[1] = x₁ pasa a bit[2]; bit[2] = x₁ + x₂ pasa a bit[4]; bit[3] = x₃ pasa a bit[4]; cuando se llega a 4, bit[4] ya tiene x₁ + … + x₄.

Dynamic Range Sum Queries

Pregunta para el grupo

El Fenwick sabe sumarle v a una posición. ¿Cómo se cambia x_k por u?

Sumándole la diferencia: sumar(k, u - x[k]), y guardando el nuevo valor en x.
La consulta es prefijo(b) - prefijo(a - 1). Todo es O((n + q) log n).

Solución · CSES 1648 · Dynamic Range Sum Queries

Cambiar es sumar la diferencia

Fenwick 
def main():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))
    bit = [0] * (n + 1)
    for i in range(1, n + 1):
        bit[i] += x[i - 1]
        j = i + (i & -i)
        if j <= n:
            bit[j] += bit[i]

    def sumar(i, v):
        while i <= n:
            bit[i] += v
            i += i & -i

    def prefijo(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s
Consultas 
    res = []
    for _ in range(q):
        t, a, b = map(int, input().split())
        if t == 1:
            sumar(a, b - x[a - 1])
            x[a - 1] = b
        else:
            res.append(prefijo(b) - prefijo(a - 1))
    print("\n".join(map(str, res)))

main()

O((n + q) log n). Con n = q = 2·10⁵ tardó 0.11 s (PyPy 3.11, Apple M4).

Problema · AtCoder Library Practice B

Fenwick Tree

Hay un arreglo a₀, …, a_{N−1} y Q consultas: "0 p x" suma x a a_p; "1 l r" pide a_l + … + a_{r−1}.

Las posiciones empiezan en 0 y el rango [l, r) no incluye r.

Entrada

Entrada

0 3 10
1 0 5
1 0 3
Salida
15

Enunciado original: https://atcoder.jp/contests/practice2/tasks/practice2_b

Es el mismo Fenwick con otra forma de numerar. La posición p del enunciado es la p + 1 del Fenwick, y a_l + … + a_{r−1} es prefijo(r) − prefijo(l). Aquí la consulta 0 suma x (no cambia el valor), así que se llama sumar(p + 1, x) directamente. El límite es 5 s. Con N = Q = 5·10⁵ tardó 0.21 s (PyPy 3.11, Apple M4).

Error común: usar las posiciones sin sumar 1, y el Fenwick se queda en un ciclo con i = 0. Caso a probar: l = 0 y r = N.

Parte 3

Actualizar un rango

El arreglo de diferencias de la semana 9, guardado en un Fenwick.

Fenwick sobre diferencias

Sumar a un rango y consultar un valor

Ejemplo de Range Update Queries después de "1 2 5 1": d[2] += 1 y d[6] −= 1. El valor de la posición 4 es x₄ + d₁ + … + d₄ = 5 + 1 = 6.

# sumar u de a a b
sumar(a, u)
sumar(b + 1, -u)

# valor actual de la posición k
x[k - 1] + prefijo(k)

El Fenwick guarda el arreglo de diferencias d. El cambio de un rango toca dos posiciones de d, y el valor de k es x_k más la suma de d hasta k. Las dos operaciones cuestan O(log n).

En la semana 9 todos los cambios llegaban antes de las consultas. Con el Fenwick se pueden mezclar.

Si b = n, sumar(n + 1, -u) no hace nada porque el bucle empieza con i > n: está bien, no hay posición después de n.

Solución · CSES 1651 · Range Update Queries

Dos cambios puntuales por rango

Fenwick vacío 
def main():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))
    bit = [0] * (n + 1)

    def sumar(i, v):
        while i <= n:
            bit[i] += v
            i += i & -i

    def prefijo(i):
        s = 0
        while i > 0:
            s += bit[i]
            i -= i & -i
        return s
Consultas 
    res = []
    for _ in range(q):
        c = list(map(int, input().split()))
        if c[0] == 1:
            a, b, u = c[1], c[2], c[3]
            sumar(a, u)
            sumar(b + 1, -u)
        else:

            res.append(x[k - 1] + prefijo(k))
    print("\n".join(map(str, res)))

Parte 4

Sparse table

Mínimo de un rango en O(1) cuando el arreglo no cambia.

Sparse table

Dos bloques de 2ᵏ que cubren el rango

La fila k guarda el mínimo de cada bloque de 2ᵏ posiciones seguidas. Hay log₂ n filas.

Un rango de largo L se cubre con dos bloques de 2ᵏ, con 2ᵏ ≤ L: uno que empieza en a y otro que termina en b. Se pueden pisar: para el mínimo, repetir un valor no cambia el resultado.

Para la suma no sirve: los valores del medio se sumarían dos veces.

Cambiar a y b para ver los dos bloques. k es el mayor entero con 2ᵏ ≤ L, que en Python es L.bit_length() - 1. Funciona igual con máximo y con gcd, que tampoco cambian si un valor se repite.

Sparse table en Python

Cada fila sale de la anterior

# tabla[k][i] = mínimo de x[i .. i + 2^k - 1]
tabla = [x]
k = 1
while (1 << k) <= n:
    prev = tabla[-1]
    mitad = 1 << (k - 1)
    tabla.append(list(map(min, prev, prev[mitad:])))
    k += 1

# mínimo de x[a .. b], desde 0
k = (b - a + 1).bit_length() - 1
min(tabla[k][a], tabla[k][b - (1 << k) + 1])

Un bloque de 2ᵏ es la unión de dos bloques de 2ᵏ⁻¹: el que empieza en i y el que empieza en i + 2ᵏ⁻¹. map(min, prev, prev[mitad:]) los compara de a pares y se detiene en la lista más corta.

Construir cuesta O(n log n) en tiempo y en memoria. Cada consulta cuesta O(1).

Con n = 10⁶, construir con map(min, ...) tardó 0.13 s y con [min(prev[i], prev[i + mitad]) for i in range(L)] 0.06 s (PyPy 3.11, Apple M4).

Las dos formas de construir alcanzan para n = 2·10⁵ (0.02 s y 0.01 s). En PyPy la comprensión de listas fue más rápida que map(min, ...). Con n = 2·10⁵ hay 18 filas.

Solución · CSES 1647 · Static Range Minimum Queries

Sparse table y dos bloques por consulta

def main():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))
    tabla = [x]
    k = 1
    while (1 << k) <= n:
        prev = tabla[-1]
        mitad = 1 << (k - 1)
        tabla.append(list(map(min, prev, prev[mitad:])))
        k += 1
    res = []
    for _ in range(q):
        a, b = map(int, input().split())
        a -= 1                  # desde 0: el rango es a..b-1
        k = (b - a).bit_length() - 1
        fila = tabla[k]
        res.append(min(fila[a], fila[b - (1 << k)]))
    print("\n".join(map(str, res)))

main()

Después de a -= 1, el rango es a..b − 1 desde 0 y su largo es b − a.

O(n log n + q). Con n = q = 2·10⁵ tardó 0.12 s (PyPy 3.11, Apple M4).

Si el arreglo cambiara, haría falta un segment tree (Dynamic Range Minimum Queries), que está fuera del programa.

Idea · CSES 1749

List Removals

Pregunta para el grupo

Si se marca con 1 cada posición original que sigue en la lista, ¿qué posición original tiene el elemento que hoy está en el lugar p?

La primera posición i con prefijo(i) = p: la p-ésima marca. Al borrarla, sumar(i, -1).
Esa i se busca bajando por el Fenwick con potencias de 2, como en una búsqueda binaria: O(log n) por borrado.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso. Una búsqueda binaria sobre prefijo(i) también funciona, pero cuesta O(log² n) por borrado.

Solución · CSES 1749 · List Removals

Buscar la p-ésima marca en el Fenwick

def main():
    n = int(input())
    x = list(map(int, input().split()))
    p = list(map(int, input().split()))
    bit = [0] * (n + 1)
    for i in range(1, n + 1):
        bit[i] += 1
        j = i + (i & -i)
        if j <= n:
            bit[j] += bit[i]
    LOG = n.bit_length()

pos avanza en bloques de 2ᵏ, de mayor a menor, mientras el bloque tenga menos de k marcas. Cada salto descuenta las marcas del bloque. Al final, pos + 1 es la k-ésima marca.

    res = []
    for k in p:
        pos = 0
        paso = 1 << LOG
        while paso:
            if pos + paso <= n and bit[pos + paso] < k:
                pos += paso
                k -= bit[pos]
            paso >>= 1
        pos += 1
        res.append(x[pos - 1])
        i = pos
        while i <= n:
            bit[i] -= 1
            i += i & -i
    print(" ".join(map(str, res)))

main()

O(n log n). Tardó 0.09 s con n = 2·10⁵ (PyPy 3.11, Apple M4).

bit[pos + paso] es la suma del bloque (pos, pos + paso] porque pos siempre es múltiplo de 2·paso. Por eso se puede leer directo, sin llamar a prefijo.

Resumen

Reglas para consultas de rango

  1. Arreglo fijo y sumas: sumas prefijas.
  2. Cambios y sumas mezclados: Fenwick, con posiciones de 1 a n.
  3. Cambiar x_k por u es sumar(k, u - x[k]).
  4. Sumar a un rango: Fenwick sobre diferencias, dos sumar por cambio.
  5. Mínimo de un rango en un arreglo fijo: sparse table con k = L.bit_length() - 1.
  6. Mínimo con cambios necesita segment tree, que queda fuera del curso.
