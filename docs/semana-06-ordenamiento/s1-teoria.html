Parte 1

Ordenar

Ordenar cuesta O(n log n) y muchas veces deja el resto del problema en O(n).

sort y sorted

Ordenar una lista

a = [5, 2, 9, 1]
a.sort()             # cambia a, devuelve None
b = sorted(a)        # lista nueva, a queda igual
a.sort(reverse=True) # de mayor a menor
s = sorted("banana") # ['a','a','a','b','n','n']

a = a.sort()         # error: a queda en None

a.sort() ordena la lista en su lugar. sorted recibe cualquier iterable (lista, string, set, map) y devuelve una lista nueva.

Los dos cuestan O(n log n). Con n = 2·10⁵ son unas 3.5·10⁶ comparaciones.

Las tuplas y los strings se comparan en orden lexicográfico, como se vio en la semana 3: primero el primer elemento y, si empatan, el segundo.

El error a = a.sort() es frecuente: el programa sigue y falla después con TypeError al usar a.

key

Ordenar con key


      

    

    

      

    

  

  
key recibe una función que se aplica a cada elemento una vez; la lista se ordena por esos valores. Para varios criterios se devuelve una tupla. -nota invierte un solo criterio; reverse=True invierte todos.
Las filas en azul tienen la misma clave. Fijarse en la columna "pos." para ver la estabilidad.






  
Estabilidad e índices

  
Los empates conservan su orden original

  

    

      
El ordenamiento de Python es estable: si dos elementos tienen la misma clave, quedan en el orden en que estaban.

      
A veces hace falta saber de qué posición venía cada valor. Para eso se ordenan los índices:

      
a = [30, 10, 50, 20]
idx = sorted(range(len(a)), key=lambda i: a[i])
# idx = [1, 3, 0, 2]
# a[idx[0]] es el menor y venía de la posición 1

      
Otra forma es ordenar parejas: sorted((a[i], i) for i in range(n)).

Idea · CSES 1090

  
Ferris Wheel

  

    
Pregunta para el grupo
El niño más pesado tiene que subir en alguna góndola. ¿Con quién conviene que suba?

    
Con el más liviano, si caben juntos. Si el más liviano no cabe con él, nadie cabe, y sube solo.

    
Se ordenan los pesos y se usan dos índices: i en el más liviano y j en el más pesado. Cada góndola mueve j, y a veces i.

  

  
Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.






  
Solución · CSES 1090 · Ferris Wheel

  
El más pesado con el más liviano

  

    

      
Pesos ordenados, x = . Cada góndola lleva hasta dos niños.

      

      

    

    
def main():
    n, x = map(int, input().split())
    p = sorted(map(int, input().split()))
    i, j = 0, n - 1
    gondolas = 0
    while i <= j:
        if i < j and p[i] + p[j] <= x:
            i += 1      # el más liviano sube con él
        j -= 1          # el más pesado sube
        gondolas += 1
    print(gondolas)

main()

  

  
El ejemplo cargado es x = 10 con pesos 7 2 3 9 más dos niños extra (5 y 8) para ver más pasos. Ordenar cuesta O(n log n) y los dos índices O(n). Con n = 2·10⁵ tardó 0.06 s (PyPy 3.11, Apple M4).

Hay n solicitantes y m apartamentos. El solicitante i quiere un apartamento de tamaño aᵢ y acepta cualquiera con tamaño entre aᵢ − k y aᵢ + k.

      
Cada apartamento es para un solo solicitante. Hay que maximizar cuántos reciben apartamento.

El máximo de solicitantes con apartamento.
Restricciones
1 ≤ n, m ≤ 2·10⁵; 0 ≤ k ≤ 10⁹

    

    

      
Entrada
4 3 5
60 45 80 60
30 60 75

      
Salida
2

    

  

  
Enunciado original: https://cses.fi/problemset/task/1084

  
Leer el enunciado con el grupo y resolver el ejemplo a mano.
Error común: para cada solicitante, buscar un apartamento entre todos, que es O(n · m). Caso a probar: k = 0, donde el tamaño tiene que ser exacto.






  
Idea · CSES 1084

  
Apartments

  

    
Pregunta para el grupo
Con las dos listas ordenadas, se compara el menor solicitante con el menor apartamento. ¿Qué se hace en cada caso?

    
Apartamento menor que a − k: no le sirve a nadie de los que faltan, que quieren más. Se descarta el apartamento.

    
Apartamento mayor que a + k: a este solicitante no le sirve ninguno de los que faltan. Se descarta el solicitante.

    
Si está en el rango, se asignan y avanzan los dos índices.

  

  
Traza del ejemplo: a = 45 60 60 80, b = 30 60 75, k = 5. El 30 se descarta (menor que 40). Para el 45, el 60 es mayor que 50: se descarta el 45. El 60 recibe el 60. Para el otro 60, el 75 es mayor que 65: se descarta. El 80 recibe el 75. Respuesta 2.






  
Solución · CSES 1084 · Apartments

  
Dos listas ordenadas, dos índices

  

    
def main():
    n, m, k = map(int, input().split())
    a = sorted(map(int, input().split()))
    b = sorted(map(int, input().split()))
    i = j = 0
    parejas = 0
    while i < n and j < m:
        if b[j] < a[i] - k:
            j += 1          # apartamento muy pequeño
        elif b[j] > a[i] + k:
            i += 1          # nada le sirve a a[i]
        else:
            parejas += 1
            i += 1
            j += 1
    print(parejas)

main()

    

      
Hay que asignar apartamentos con tamaño entre a − k y a + k al mayor número de solicitantes.

      
Cada vuelta avanza i, j o los dos. El bucle hace a lo sumo n + m vueltas.

      
El total es O(n log n + m log m) por los dos ordenamientos. Con n = m = 2·10⁵ tardó 0.09 s (PyPy 3.11, Apple M4).

Solución · CSES 1619 · Restaurant Customers

  
Recorrer llegadas y salidas en orden

  

    

      
Máximo de clientes dentro al mismo tiempo.

      

      

    

    
def main():
    n = int(input())
    llega, sale = [], []
    for _ in range(n):
        a, b = map(int, input().split())
        llega.append(a)
        sale.append(b)
    llega.sort()
    sale.sort()
    j = dentro = mejor = 0
    for a in llega:
        while sale[j] < a:    # salieron antes
            dentro -= 1
            j += 1
        dentro += 1
        mejor = max(mejor, dentro)
    print(mejor)

main()

Parte 3

  
Búsqueda binaria

  
En una lista ordenada, cada pregunta descarta la mitad de las posiciones.






  
Búsqueda binaria

  
Primera posición con a[i] ≥ x

  

    

    

    

  

  

    

      
lo, hi = 0, n
# la respuesta está en [lo, hi]
while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] >= x:
        hi = mid      # mid sirve
    else:
        lo = mid + 1  # mid no sirve
# lo == hi: la respuesta (n si no hay)

    

    

      
Cada vuelta deja el rango en la mitad. Con n = 10⁶ son unas 20 vueltas.

      
Si a[mid] >= x, mid puede ser la respuesta y también puede haber otra antes. Si no, mid y todo lo anterior quedan descartados.

    

  

  
Probar con x = 23 (no está; la respuesta es la posición del 25), x = 18 (hay repetidos; la respuesta es el primero), x = 1 (respuesta 0) y x = 99 (respuesta n = 12).






  
Invariante

  
Cómo evitar los errores de ±1

  

    

      
El invariante es lo que se cumple al empezar cada vuelta: la respuesta está entre lo y hi. Las dos ramas lo conservan.

      
    
        
  • a[mid] >= x: mid podría ser la respuesta, así que se guarda con hi = mid.
    • 
        
  • a[mid] < x: mid y todo lo anterior quedan descartados, así que lo = mid + 1.
    • 
      

      
Como mid < hi, las dos ramas achican el rango y el bucle termina.

    

    

      
Errores frecuentes

      
    
        
  • while lo <= hi con hi = mid: cuando lo == hi, el bucle no avanza.
    • 
        
  • lo = mid en lugar de mid + 1: con hi = lo + 1, mid es lo y el bucle no avanza.
    • 
        
  • Empezar con hi = n - 1: si ningún valor es ≥ x, la respuesta n no está en el rango.
    • 
        
  • Buscar en una lista sin ordenar.
    • 
      

    

  

  
Recomendar una sola plantilla (esta) y usarla siempre. La búsqueda de "último valor ≤ x" sale de esta misma: es la primera posición con a[i] > x, menos 1.






  
bisect

  
bisect_left y bisect_right

  

    

    

    

  

  

    

      
,]

      

      
Se importan con from bisect import bisect_left, bisect_right. Cada llamada es O(log n) y la lista debe estar ordenada.

    

    

      
bisect_left(a, x)    # primera posición con a[i] >= x
bisect_right(a, x)   # primera posición con a[i] > x

# cuántos valores son iguales a x
bisect_right(a, x) - bisect_left(a, x)
# cuántos valores hay en [l, r]
bisect_right(a, r) - bisect_left(a, l)
# cuántos valores son <= x
bisect_right(a, x)

    

  

  
bisect_left hace lo mismo que la búsqueda manual de la diapositiva anterior. Con 10⁶ consultas sobre 10⁶ valores, la manual tardó 0.14 s y bisect_left 0.16 s (PyPy 3.11, Apple M4). Contar recorriendo la lista tardó 1.47 s con solo 10³ consultas.

Solución · Codeforces 706B · Interesting Drink

  
Contar precios ≤ m

  

    
from bisect import bisect_right

def main():
    n = int(input())
    x = sorted(map(int, input().split()))
    q = int(input())
    res = []
    for _ in range(q):
        m = int(input())
        res.append(bisect_right(x, m))
    print("\n".join(map(str, res)))

main()

    

      
Para cada día hay que contar en cuántas tiendas el precio es ≤ m.

      
Se ordena una vez, O(n log n), y cada día es O(log n). El total es O((n + q) log n).

Parte 4

  
Búsqueda binaria sobre la respuesta

  
Buscar el menor valor que cumple una condición.






  
Búsqueda sobre la respuesta

  
Cuando la condición pasa de falso a verdadero una sola vez

  

    

      
Muchos problemas piden "el mínimo T tal que se puede…". Si con T se puede, con T + 1 también. Entonces la condición es monótona:

      
F F F F F V V V V V V

      
La respuesta es el primer V. Se encuentra con la misma búsqueda binaria, con la pregunta puede(mid) en el if.

      
Si puede cuesta O(n) y la respuesta está entre 1 y H, el total es O(n log H).

    

    
def puede(T):
    ...   # True si con T alcanza

lo, hi = 1, H        # puede(H) es True
while lo < hi:
    mid = (lo + hi) // 2
    if puede(mid):
        hi = mid
    else:
        lo = mid + 1
print(lo)

  

  
Dos decisiones: escribir puede y elegir un H con puede(H) verdadero. Con H = 10¹⁸ son unas 60 vueltas, así que H puede ser holgado.

Idea · CSES 1620

  
Factory Machines

  

    
Pregunta para el grupo
Si el tiempo es T, ¿cuántos productos se hacen? ¿Qué pasa con esa cantidad cuando T crece?

    
Se hacen T // k₁ + T // k₂ + … + T // kₙ. La suma nunca baja cuando T crece.

    
Se busca el menor T con suma ≥ t. Con la máquina más rápida sola se llega en min(k) · t, así que ese es H.

  

  
Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.






  
Solución · CSES 1620 · Factory Machines

  
El menor T que alcanza

  

    

      
k = 3 2 5, t = 7. Cada celda es un T con los productos que se hacen.

      

      

    

    
def main():
    n, t = map(int, input().split())
    k = list(map(int, input().split()))

    def alcanza(T):
        total = 0
        for x in k:
            total += T // x
            if total >= t:
                return True
        return False

    lo, hi = 1, min(k) * t
    while lo < hi:
        mid = (lo + hi) // 2
        if alcanza(mid):
            hi = mid
        else:
            lo = mid + 1
    print(lo)

main()

  

  
H = min(k) · t ≤ 2·10¹⁴, así que son unas 48 vueltas de O(n): cerca de 10⁷ operaciones. Con la entrada máxima tardó 0.05 s (PyPy 3.11, Apple M4). El return True adelantado evita sumar números grandes sin necesidad.
