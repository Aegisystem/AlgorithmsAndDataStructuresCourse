Programación competitiva

Un problema, un programa y un juez

En programación competitiva se escribe un programa que resuelve un problema descrito en un enunciado.

  • El programa lee la entrada estándar y escribe en la salida estándar.
  • Un juez en línea ejecuta el programa con casos de prueba ocultos.
  • Cada caso tiene un límite de tiempo (por lo general 1 o 2 segundos) y un límite de memoria (por lo general 256 MB).
  • La solución es correcta solo si pasa todos los casos.

Qué se practica

  • Leer un problema y modelarlo.
  • Elegir un algoritmo que quepa en el tiempo.
  • Programarlo sin errores.
  • Probarlo con casos borde antes de enviar.

Insistir en que pasar los ejemplos del enunciado no basta: el juez usa casos más grandes y casos borde.

Las rondas Div. 3, Div. 4 y Educational de Codeforces usan reglas tipo ICPC. En todos los formatos, un envío rechazado en un problema que nunca se resuelve no suma penalización.

No hace falta memorizar los detalles. La idea es que entiendan que enviar sin probar cuesta penalización.

Ranking ICPC

Cómo se calcula la penalización

EquipoABCResueltosPenalización
Rojo+ 25'+1 40'−2285
Azul+2 30'+ 50'2120
Verde+ 10'−3+ 100'2110

+1 40' significa: resuelto en el minuto 40, con 1 envío rechazado antes.

Penalización = suma, en los problemas resueltos, del minuto del AC + 20 por cada rechazo previo.

Rojo: 25 + (40 + 20) = 85

Azul: (30 + 40) + 50 = 120

Verde: 10 + 100 = 110. Los 3 rechazos en B no cuentan.

Orden final: Rojo, Verde, Azul.

Preguntar al grupo el orden antes de revelar la columna. Muchos piensan que Verde pierde por los 3 rechazos en B.

Enunciado

  
Anatomía de un enunciado

  

    

      
Weird Algorithm (CSES), versión resumida

        Un algoritmo recibe un entero positivo n. Si n es par, lo divide entre 2. Si n es impar, lo multiplica por 3 y le suma 1. Repite hasta que n sea 1. Debe simular el algoritmo para un n dado.

      
Entrada
Una única línea con el entero n.

      
Salida
Imprimir en una línea todos los valores que toma n, separados por espacios.

      
Restricciones
1 ≤ n ≤ 10⁶

      
Ejemplo
Entrada: 3
Salida:  3 10 5 16 8 4 2 1

    

    

      

      

    

  

  
Recorrer las cinco partes. Preguntar: ¿qué dato de las restricciones nos dice que la respuesta puede pasar de 10⁶? (los valores intermedios crecen: con n = 704 511 se llega a 56 991 483 520).







  
Restricciones

  
Qué dicen las restricciones

  

    

      
Tamaño de la entrada
n ≤ 2·10⁵ o n ≤ 10⁶ dice cuántas operaciones caben. Con 10⁶ números hay que leer rápido (lo vemos en un momento).

      
Rango de los valores
aᵢ ≤ 10⁹ y n ≤ 2·10⁵ hacen que la suma llegue a 2·10¹⁴. En C++ eso no cabe en un int. En Python los enteros no tienen límite.

    

    

      
Número de casos
"La primera línea tiene t, el número de casos". A veces se garantiza que la suma de n en todos los casos no pasa de 2·10⁵.

      
Garantías
"Los números son distintos", "existe al menos una respuesta". Cada garantía elimina un caso que no hay que programar.

    

  

  
En la semana 2 se usa la tabla de restricciones contra complejidad. Hoy basta con que lean las restricciones antes de programar.

Entrada y salida

  
Leer y escribir en Python

  

    
def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(sum(a))

main()

    
    
      
  • input() lee una línea de la entrada y la devuelve como string.
    • 
      
  • int() convierte el string en número. split() separa la línea por espacios.
    • 
      
  • print() escribe y agrega un salto de línea. print(*a) imprime una lista separada por espacios.
    • 
      
  • Todo el código va dentro de main().
    • 
    

  

  
Pedir que guarden este esquema como archivo base. En la semana 4 se ve una forma más rápida de leer y escribir, que hace falta cuando la entrada tiene 10⁵ líneas o más.







  
Lectura

  
Formatos de entrada comunes

  

    
# un entero
n = int(input())

# varios enteros en una línea
n, k = map(int, input().split())
a = list(map(int, input().split()))

# un string
s = input()

    
# t casos de prueba
t = int(input())
for _ in range(t):
    n = int(input())

CSES 1068 · Weird Algorithm

  
Simular el algoritmo paso a paso

  

    

      

      

      

      
    

    

      
def main():
    n = int(input())
    out = [n]
    while n != 1:
        if n % 2 == 0:
            n //= 2
        else:
            n = 3 * n + 1
        out.append(n)
    print(*out)

main()

      
Usar // y no /: n / 2 da un float y se imprime 5.0.

    

  

  
Probar n = 27: hace 111 pasos y llega a 9232. La simulación es directa; el error típico es imprimir floats o imprimir un valor por línea.







  
CSES 1083 · Missing Number

  
Encontrar el número que falta

  

    

      
Se dan n − 1 números distintos entre 1 y n. Hay que encontrar el que falta. Ejemplo: n = 5, números 2 3 1 5.

      

        
11

        
22

        
33

        
4?

        
55

      

      

        
Suma de 1 a n: n(n+1)/2 = 15

        
Suma de los dados: 2+3+1+5 = 11

        
Falta: 15 − 11 = 4

      

    

    

      
def main():
    n = int(input())
    a = list(map(int, input().split()))
    total = n * (n + 1) // 2
    print(total - sum(a))

main()

      
Hace una sola pasada sobre los datos: O(n). Ordenar y buscar el hueco también funciona, pero cuesta O(n log n).

    

  

  
Con n = 2·10⁵, la suma llega a unos 2·10¹⁰. En Python no hay desbordamiento. Mencionar la alternativa con XOR como curiosidad (se ve en la semana 8).







  
CSES 1069 · Repetitions

  
La racha más larga de un mismo carácter

  

    

      

      

      

    

    
def main():
    s = input()
    best = cur = 1
    for i in range(1, len(s)):
        if s[i] == s[i - 1]:
            cur += 1
            if cur > best:
                best = cur
        else:
            cur = 1
    print(best)

main()

  

  
Probar con ATTCGGGA y con un string de un solo carácter.







  
CSES 1094 · Increasing Array

  
Mínimo de movimientos para que no decrezca

  

    

      

      

      

    

    

      
Un movimiento suma 1 a un elemento. Si a[i] es menor que el anterior, hay que subirlo hasta igualarlo.

      
def main():
    n = int(input())
    a = list(map(int, input().split()))
    moves = 0
    mx = a[0]
    for x in a:
        if x < mx:
            moves += mx - x
        else:
            mx = x
    print(moves)

main()

    

  

  
Preguntar por qué subir al mínimo necesario es óptimo: subir más solo obliga a subir más a los siguientes. Es la primera idea greedy del curso.
