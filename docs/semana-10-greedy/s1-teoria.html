Parte 1

Algoritmos greedy

Escoger en cada paso lo que mejor se ve y no volver atrás.

Greedy

Dar el cambio con la moneda más grande

greedy
mínimo

Un algoritmo greedy (voraz) toma en cada paso la opción que mejor se ve en ese momento y no la cambia después.

Para dar cambio, el greedy usa la moneda más grande que quepa, una y otra vez.

Con monedas 1, 5, 10 y 25 siempre da el mínimo. Con monedas 1, 3 y 4 y monto 6 da 4 + 1 + 1, tres monedas, y el mínimo es 3 + 3.

Probar el monto 6 con las dos opciones de monedas. Un solo caso en el que el greedy falla, un contraejemplo, basta para descartarlo. El mínimo de monedas con cualquier sistema se calcula con programación dinámica en la semana 14 (Minimizing Coins).

Contraejemplos

Antes de programar un greedy

  1. Escribir la regla en una frase: "tomar la película que termina primero".
  2. Buscar un contraejemplo a mano, con 2 o 3 elementos.
  3. Si no aparece, comparar el greedy con una búsqueda completa en muchos casos pequeños al azar.
  4. Buscar el argumento: por qué la elección no puede empeorar la respuesta.

Las soluciones del curso se revisaron así, contra una búsqueda completa en casos pequeños.

import random

for _ in range(1000):
    n = random.randint(1, 6)
    a = [random.randint(1, 10) for _ in range(n)]
    if greedy(a) != completa(a):
        print("contraejemplo:", a)
        break

completa prueba todas las opciones (semana 11). Con n ≤ 6 es rápida. Si el greedy falla, el programa imprime un caso pequeño que se puede revisar a mano.

Problema · CSES 1629

Movie Festival

En un festival hay n películas, cada una con hora de inicio a y de fin b. Hay que ver el máximo de películas completas, sin ver dos a la vez.

Entrada
n; n líneas con a y b.
Salida
El máximo de películas.
Restricciones
1 ≤ n ≤ 2·10⁵; 1 ≤ a < b ≤ 10⁹
Entrada
3
3 5
4 9
5 8
Salida
2

Enunciado original: https://cses.fi/problemset/task/1629

Leer el enunciado con el grupo y resolver el ejemplo a mano: 3 5 y 5 8. Una película puede empezar justo cuando termina otra.

Error común: escoger por hora de inicio o por duración (ver la idea). Otro: usar a > libre en lugar de a >= libre. Caso a probar: 1 2 y 2 3, cuya respuesta es 2.

Idea · CSES 1629

Movie Festival

Pregunta para el grupo

¿Qué película conviene ver primero: la que empieza antes, la más corta o la que termina antes?

La que empieza antes falla con 1–10, 2–3 y 4–5: escoge 1–10 y ve una sola.
La más corta falla con 1–5, 4–7 y 6–10: escoge 4–7 y ve una sola.
La que termina antes deja libre la mayor parte del tiempo. Se ordenan por fin y se toma cada película que empiece después de la última vista.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar los contraejemplos.

Por qué funciona: si una solución óptima empieza con otra película, se puede cambiar por la que termina antes. Esa termina igual o antes, así que el resto de la solución sigue siendo válido y la cantidad no cambia.

Solución · CSES 1629 · Movie Festival

Ordenar por la hora de fin

def main():
    n = int(input())
    pelis = []
    for _ in range(n):
        a, b = map(int, input().split())
        pelis.append((b, a))
    pelis.sort()
    libre = cuenta = 0
    for b, a in pelis:
        if a >= libre:
            cuenta += 1
            libre = b
    print(cuenta)

main()

Las tuplas van como (fin, inicio) para que sort ordene por el fin. libre es la hora desde la que se puede empezar otra película. O(n log n) por el ordenamiento. Con n = 2·10⁵ tardó 0.21 s (PyPy 3.11, Apple M4).

Hay que encontrar el costo total mínimo.

Entrada

Salida
El costo mínimo.
Restricciones
1 ≤ n ≤ 2·10⁵; 1 ≤ pᵢ ≤ 10⁹
Entrada
5
2 3 1 5 2
Salida

Enunciado original: https://cses.fi/problemset/task/1074

Leer el enunciado con el grupo y resolver el ejemplo a mano: con longitud 2 el costo es 0 + 1 + 1 + 3 + 0 = 5.

Error común: usar el promedio. Con 1 1 10 el promedio es 4 y cuesta 12; la mediana es 1 y cuesta 9. Otro: probar cada longitud posible, O(n²). Caso a probar: n = 1, con costo 0.

Solución · CSES 1074 · Stick Lengths

La mediana minimiza la suma de distancias

Si la longitud final está a la izquierda de la mediana, hay más palos a la derecha que a la izquierda. Moverla una unidad a la derecha baja el costo.

def main():
    n = int(input())
    p = sorted(map(int, input().split()))
    m = p[n // 2]          # la mediana
    print(sum(abs(x - m) for x in p))

main()

Mover el control y ver cómo cambia el costo: es mínimo en la mediana. Con n par, cualquier valor entre las dos medianas da el mismo costo; p[n // 2] sirve. O(n log n). Con n = 2·10⁵ tardó 0.06 s (PyPy 3.11, Apple M4).

Idea · CSES 1643

Maximum Subarray Sum

Pregunta para el grupo

Se conoce la mejor suma de un subarreglo que termina en la posición i − 1. ¿Cuál es la mejor que termina en la posición i?

O se extiende el subarreglo anterior, o se empieza uno nuevo en i: actual = max(a[i], actual + a[i]).
Si la suma anterior es negativa, conviene empezar de nuevo. La respuesta es el mayor actual visto. Es O(n).

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso. Es una programación dinámica de un solo valor; en la semana 14 se ven más.

Solución · CSES 1643 · Maximum Subarray Sum

Seguir o empezar de nuevo

def main():
    n = int(input())
    a = list(map(int, input().split()))
    mejor = actual = a[0]
    for i in range(1, n):
        actual = max(a[i], actual + a[i])
        mejor = max(mejor, actual)
    print(mejor)

main()

Las casillas marcadas son el subarreglo que da actual. Con n = 2·10⁵ tardó 0.04 s (PyPy 3.11, Apple M4).

Parte 4

Orden de las tareas

Un argumento de intercambio.

Problema · CSES 1630

Tasks and Deadlines

Hay n tareas, cada una con duración a y plazo d. Se hacen todas, una tras otra, desde el tiempo 0. Si una tarea termina en el tiempo f, da d − f puntos, que pueden ser negativos.

Hay que encontrar el máximo de puntos.

Entrada
n; n líneas con a y d.
Salida
El máximo de puntos.
Restricciones
1 ≤ n ≤ 2·10⁵; 1 ≤ a, d ≤ 10⁶
Entrada
3
6 10
8 15
5 12
Salida
2

Enunciado original: https://cses.fi/problemset/task/1630

Leer el enunciado con el grupo y resolver el ejemplo a mano. En el orden 5, 6, 8 las tareas terminan en 5, 11 y 19: (12 − 5) + (10 − 11) + (15 − 19) = 2.

Error común: ordenar por plazo. Con las tareas (a = 10, d = 10) y (a = 1, d = 11), ordenar por plazo da 0 puntos y ordenar por duración da 9. Caso a probar: n = 1.

Idea · CSES 1630

Tasks and Deadlines

Pregunta para el grupo

Los puntos son la suma de los plazos menos la suma de los tiempos de fin. ¿Qué parte depende del orden?

Solo la suma de los tiempos de fin. Hay que hacerla lo más pequeña posible.
Si una tarea larga va justo antes de una corta, intercambiarlas baja esa suma. Por eso van de la más corta a la más larga, y los plazos no importan.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso.

El intercambio: si la tarea x va antes que y y empiezan en t, los fines suman (t + aₓ) + (t + aₓ + a_y). En el otro orden suman (t + a_y) + (t + a_y + aₓ). La diferencia es aₓ − a_y, así que conviene la corta primero. Las demás tareas no cambian.

Solución · CSES 1630 · Tasks and Deadlines

De la más corta a la más larga

def main():
    n = int(input())
    duraciones = []
    total = 0
    for _ in range(n):
        a, d = map(int, input().split())
        duraciones.append(a)
        total += d
    duraciones.sort()
    t = 0
    for a in duraciones:
        t += a          # fin de esta tarea
        total -= t
    print(total)

main()

O(n log n) por el ordenamiento.

Los plazos solo se suman, así que no hace falta guardarlos.

Con n = 2·10⁵ tardó 0.09 s (PyPy 3.11, Apple M4).

La respuesta puede llegar a unos −2·10¹⁶ (todas las tareas largas y con plazo 1). En Python no hay desbordamiento.

Parte 5

Colas de prioridad

Sacar el menor una y otra vez, mientras llegan elementos nuevos.

heapq

Un heap es una lista con el menor en la posición 0

from heapq import heappush, heappop, heapify

h = []
heappush(h, 5)      # O(log n)
heappush(h, 1)
heappush(h, 8)
h[0]                # 1, el menor: O(1)
heappop(h)          # saca el 1: O(log n)

a = [5, 1, 8, 3]
heapify(a)          # O(n)

Cada nodo es menor o igual que sus hijos. Los hijos de la posición i están en 2i + 1 y 2i + 2.

Agregar algunos valores con heappush y sacar con heappop. Al agregar, el valor sube mientras sea menor que su padre. Al sacar, el último pasa a la raíz y baja. El árbol tiene log n niveles, por eso cada operación cuesta O(log n). La lista no queda ordenada: solo h[0] es seguro el menor.

heapq

Máximos, tuplas y los k mayores

# max-heap: guardar los valores negados
heappush(h, -x)
mayor = -heappop(h)

# tuplas: se compara el primer elemento,
# y si empatan, el segundo
heappush(h, (prioridad, dato))

# los k mayores de una secuencia
h = []
for x in a:
    heappush(h, x)
    if len(h) > k:
        heappop(h)      # sale el menor
# h[0] es el k-ésimo mayor

En una tupla, si la prioridad empata se compara el dato. Si el dato no se puede comparar (por ejemplo, una lista con un dict), se agrega un contador como segundo elemento.

2

Idea · CSES 1164

Room Allocation

Pregunta para el grupo

Se atiende a los clientes por orden de llegada. Cuando llega uno, ¿qué cuarto ocupado conviene revisar?

El que se libera primero. Si ese no está libre, ninguno lo está y hace falta un cuarto nuevo.
Un heap guarda (día de salida, cuarto) de los cuartos ocupados. h[0] es el que se libera primero.

Dejar uno o dos minutos para que el grupo responda. Después avanzar con → para mostrar la idea paso a paso. La cantidad de cuartos es el máximo de clientes en el hotel a la vez, como en Restaurant Customers (semana 6).

Solución · CSES 1164 · Room Allocation

El cuarto que se libera primero

from heapq import heappush, heappop

def main():
    n = int(input())
    c = [tuple(map(int, input().split())) for _ in range(n)]
    orden = sorted(range(n), key=lambda i: c[i][0])
    ocupados = []           # (salida, cuarto)
    cuarto = [0] * n
    k = 0
    for i in orden:
        a, b = c[i]
        if ocupados and ocupados[0][0] < a:
            _, r = heappop(ocupados)
        else:
            k += 1
            r = k
        cuarto[i] = r
        heappush(ocupados, (b, r))
    print(k)
    print(" ".join(map(str, cuarto)))

main()

El ejemplo cargado tiene seis clientes. O(n log n). Con n = 2·10⁵ tardó 0.23 s (PyPy 3.11, Apple M4).

Resumen

Reglas para greedy y heaps

  1. Un greedy se descarta con un solo contraejemplo. Buscarlo con casos pequeños antes de programar.
  2. Intervalos: ordenar por el fin y tomar los que empiezan después del último tomado.
  3. Suma de distancias mínima: la mediana.
  4. Kadane: actual = max(a[i], actual + a[i]).
  5. heappush y heappop en O(log n); h[0] es el menor. Para el mayor, guardar −x.
  6. Heap cuando se mezclan inserciones con "sacar el menor".
